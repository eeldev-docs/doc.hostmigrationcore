HostMigrationCore 1.2.1

November 27, 2026

Fix release on top of 1.2.0. There are no new settings, no new Blueprint nodes and no changes to the saved snapshot format.

Fixed​

  • Graceful handover.
    • The host takes one snapshot when the handover starts and sends that same snapshot to every client.
    • The host waits until each client has acknowledged that snapshot and has no chunks left to receive. A client that stops receiving chunks for 10 s (longer when a bandwidth cap is set) no longer holds the host back.
    • Calling handover again, or closing the window again, while a handover is already running does nothing.
    • Leaving the session while the window is being closed is ignored until the handover is done.
  • Owner restoration.
    • Actors whose owner was a player controller get that owner back when the player joins the new host, also when the player joins late or comes back as an inactive player.
    • Pending owners are dropped when the actor is destroyed, when the player's inactive time expires, and when the map changes.
    • A pending owner is also written into new snapshots, so a second migration does not lose it.
  • Restore order. Dynamic components are now added to all restored actors first and the saved data is read afterwards, also for placed actors in levels that load later. A saved component whose class has changed is skipped instead of being read with the wrong layout.
  • Snapshot size checks. A snapshot that is empty, that decompresses to more than 64 MB, or whose chunk count is out of range is refused on the host instead of being queued.
  • Full snapshot request. A client that asks for a full snapshot now also resets its acknowledged sequence.
  • EOS. Pending and in-flight attribute writes are discarded when the lobby changes. A write for the old lobby is no longer sent to the new one or retried after the old lobby is gone.
  • Steam. The lobby owner data is compared to the exact new value and written whenever it differs, and OWNINGID and OWNINGNAME no longer depend on P2PADDR changing.

Upgrade notes​

  • Drop-in replacement for 1.2.0. No settings or assets need to change.
  • Handover now waits for the final snapshot to be fully acknowledged. With a very low Max Snapshot Bytes Per Second Per Client and a large world, the host can take longer to leave.

HostMigrationCore 1.2.0

November 21, 2026

Unreal Engine 5.8. Steam, EOS and Null adapters.

Added​

  • Level streaming and World Partition. Placed actors in levels that are not loaded yet are restored when their level is added. Until then their saved state stays in new snapshots.
  • Destroy Unsaved Runtime Actors (on by default) and Keep Unsaved Runtime Actor Classes. After a restore, the new host removes actors with a Host Migration Id that the game spawned itself but that are not in the snapshot. Controllers, PlayerStates, the GameState, the GameMode and player pawns are never removed.
  • Max Snapshot Bytes Per Second Per Client caps snapshot traffic per client. 0 means no limit.
  • On Migration Failed event, Get Last Failure Reason, and the settings Travel On Failure and Failure Travel URL. With Travel On Failure off, your game decides what happens.
  • Keep Client Join Options (on by default), Reconnect URL Options and the node Set Reconnect URL Options. Clients reconnect with ?Name=, passwords and your own login options.
  • Heartbeat Interval and Heartbeat Timeout settings (defaults 5 s and 15 s).
  • Successor Score Hysteresis (default 30 ms) keeps the successor order stable.
  • Manage Lobby Ownership (on by default) controls whether the Steam and EOS adapters make the host the lobby owner.
  • Steam: the lobby is also found through the online subsystem's game session when it was joined before the adapter started listening. A warning is logged after 10 s in a networked match without a lobby.

Changed​

  • Client Wait Map is optional. Without it, clients stay in the match world with the connection closed while they wait for the new host. The engine's disconnect travel is held back during a migration and for 1.5 s after the host closes the connection.
  • Delta snapshots. The host keeps the hashes of the last 8 states, so a client that is a few snapshots behind gets a delta from the state it holds.
  • Graceful handover waits until the clients have acknowledged the last snapshot (up to 5 s) before the host leaves.
  • Kick detection. A removed local PlayerController counts as a kick only after 1 s, and only if the connection is still open, no new PlayerController has arrived and no map change is running.
  • Successor order. Equal pings are ordered by net id. Small ping changes no longer reorder or resend the list.
  • EOS adapter. Uses the platform where the local player's product user id is logged in (PIE, EOSCore), uses the online subsystem of the game instance's own world, merges attribute writes into one lobby update at a time, and retries after "too many requests".
  • The failure message of an earlier migration no longer shows on the overlay when a new migration starts.

Fixed​

  • Chunks of an abandoned snapshot transfer could be mixed with a new one. A new transfer now starts at chunk 0.
  • A duplicated actor could carry the same Host Migration Id as the original. The id is now transient and not copied on duplicate, and a warning is logged on id collisions.
  • A changed Host Migration Id was not replicated to clients after it was reassigned.
  • The new host could save and resend stale state for placed actors in not-yet-loaded levels.
  • Compile errors in strict (non-unity) builds and packaged plugin builds.
  • Compile error on UE 5.7 caused by GetPhysicsLinearVelocity.

Upgrade notes​

  • No changes to the saved snapshot format are required for these fixes.
  • If your game uses the lobby owner for something else, turn off Manage Lobby Ownership.
  • If your game spawns actors with a Host Migration Id at runtime on its own, check Destroy Unsaved Runtime Actors and, if needed, add classes to Keep Unsaved Runtime Actor Classes.
  • The Steam and EOS modules now depend on OnlineSubsystemUtils (the Build.cs files are updated).
  • Custom PlayerState variables are only carried over seamless travel if you copy them in CopyProperties. This is Unreal behaviour; see Map changes.

HostMigrationCore 1.1.3

November 10, 2026

Added​

  • The debug overlay displays the player's role, migration state, epoch, current host, successor list, snapshots, and lobby.
  • Move Party To Host sends the connected clients to another host before moving the current host.

  • Added On Host Connection Lost.

Changed​

  • When the plugin finds multiple hosts, it prefers the one with the newest epoch and uses player count as a tiebreaker.
  • Switching lobbies mid-match is treated as leaving the match.
  • Steam and EOS automatically rejoin the match lobby if a player loses membership during play.

HostMigrationCore 1.1.1 / 1.1.2

November 8, 2026

Added​

  • Wait For Game Ready lets games such as Lyra defer restoring the snapshot until they call Notify Game Ready. Is Restore Pending lets the game skip setup such as a new warmup, and Game Ready Timeout resumes restoration if the signal never arrives.
  • Restore Into Game Pawn applies the returning player's saved state and position to the pawn spawned by the game. Players who reconnect later also wait for their game-spawned pawn.
  • Added the Lyra Sample Project tutorial.
  • Is Host Migration Network Failure lets a session plugin's error handler identify migration-related failures and keep the session open.

Fixed​

  • The successor carries over the previous host's map URL options, including game mode parameters such as ?Experience=X?NumBots=0.
  • Clients that lose lobby membership during migration no longer start a second host. Steam and EOS clients try to rejoin the lobby, then fall back to connecting directly to the successor's platform address.

HostMigrationCore 1.1.0

October 31, 2026

Added​

  • Added the EOS Adapter in the HostMigrationCoreEOS module. It discovers the lobby, tracks who is still in the match, and advertises the new host through member attributes. It keeps lobby ownership with the current host so Join Session still works after a handoff. It supports OnlineSubsystemEOS, EOSCore 1.9.8.9 or later, and direct EOS SDK integrations.
  • An empty Adapter Class now selects the EOS Adapter automatically when DefaultPlatformService is EOS or EOSCore.

Changed​

  • Renamed Steam Lobby to Steam Adapter in Project Settings. Existing configurations still work.

Fixed​

  • During non-seamless ServerTravel, clients that miss the map change can reconnect if the host remains in the session. This handles cases such as EOS closing the host's P2P socket while the map loads.
  • The warning about using the Null adapter with a Steam or EOS net driver now identifies the corresponding adapter.
  • Get Steam Lobby and Get EOS Lobby are now callable in Blueprint. Their C++ versions are static and take a world context, like the corresponding setters.

HostMigrationCore 1.0.3

October 24, 2026

Added​

  • Added the Connect Attempt Timeout setting.

Fixed​

  • Resolved a crash when the host election picked a client that was still trying to rejoin the host.
  • Fixed clients disconnecting a few seconds after they reached the new host.
  • Restored the previous host's state and pawn on reconnection during the grace period.
  • Corrected rejoin handling for host addresses that contain a colon.
